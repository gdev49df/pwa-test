# ддх воркер: ии и пуш-уведомления

прокси между приложением и groq, плюс рассылка пушей для напоминаний. ключ groq хранится только в секрете воркера, в браузер и в репозиторий он не попадает.

## как запустить (через сайт cloudflare)

1. dash.cloudflare.com → Workers & Pages → Create → Create Worker, имя `ddx-ai`, Deploy.
2. Edit code → вставь содержимое `index.js` → Deploy.
3. Settings → Variables and Secrets:
   - Secret `GROQ_API_KEY` = ключ из console.groq.com (API Keys)
   - Text `ALLOWED_ORIGINS` = `https://gdev49df.github.io`
4. скопируй адрес воркера (вида `https://ddx-ai.твой-ник.workers.dev`) и вставь в `planner/config.js` в `ai.url`.

## защита

- воркер отвечает только сайтам из `ALLOWED_ORIGINS`
- фото до 600 КБ, ответ ограничен по длине
- в приложении есть дневной лимит запросов для бесплатного тарифа (`limits.aiDay`)
- для надёжности в панели cloudflare добавь Rate limiting rule на воркер (Security → WAF → Rate limiting)
- в console.groq.com следи за лимитами ключа

## пуш-уведомления (напоминания при закрытом приложении)

нужны три вещи в cloudflare, один раз:

1. хранилище: Workers & Pages → KV → Create a namespace, имя `ddx-push`.
2. привязка: воркер `ddx-ai` → Settings → Bindings → Add → KV namespace, имя переменной строго `KV`, выбрать `ddx-push`.
3. расписание: воркер → Settings → Trigger Events → Add → Cron Trigger → `* * * * *` (каждую минуту).

потом заново вставь `index.js` в Edit code и Deploy. ключи vapid воркер создаёт сам при первом запросе и хранит в KV, ничего вводить не надо.

в приложении: добавить на экран «Домой» (iOS 16.4+), открыть Настройки → «включить пуш-уведомления» → «проверить пуш».

как это работает: при каждом изменении задач приложение отправляет воркеру список ближайших напоминаний, а cron раз в минуту шлёт пуши на те, время которых пришло. точность до минуты.

## лимиты ии (считаются на сервере)

воркер сам считает запросы к ии по устройству и дню (нужен KV), поэтому обойти лимит через консоль браузера нельзя.

- бесплатно: 10 вопросов и 2 фото еды в день
- pro: 40 вопросов и 15 фото в день
- общий предохранитель: 1500 запросов в день на всех (константа `GLOBAL_DAY` в index.js)
- день считается по времени астаны (переменная `TZ_OFFSET`, по умолчанию 5)
- если запрос к модели не удался, попытка возвращается

проверка pro на сервере: хеши кодов активации зашиты прямо в `index.js` (блок между `CODES-BEGIN` и `CODES-END`), переменную cloudflare заводить не нужно (у неё лимит 5 КБ). код привязывается к первому устройству, которое им воспользовалось, второе устройство получит бесплатные лимиты. после новых кодов запусти `node tools/make-code.js M 50`, он сам обновит и config.js, и воркер, потом заново вставь `index.js` в воркер.

числа лимитов: на сервере `FREE_Q` и `PRO_Q` в index.js, в приложении `limits.aiAskDay`, `limits.aiFoodDay` и `proAi` в `planner/config.js`. меняй в обоих местах одинаково.


## Аккаунты (D1)

С версии 2.1 вход в приложение обязателен: логин и пароль, облачная копия данных и Pro лежат в базе D1.

1. База `ddx-db` уже создана. В панели Cloudflare: Workers & Pages → `ddx-ai` → Settings → Bindings → Add → D1 database → имя переменной `DB`, база `ddx-db`.
2. Вставь новый `index.js` в воркер и нажми Deploy. Таблицы (users, sessions, data, codes) создаются сами при первом запросе.
3. Пароли хранятся как PBKDF2-SHA256 (100 000 кругов) с солью, токены входа в базе только в виде sha-256.
4. Ограничения: 5 регистраций с одного адреса в день, 10 неудачных входов в час на логин, облачный документ до 900 КБ.
5. Код активации привязывается к аккаунту навсегда и второй раз не сработает ни у кого.
6. Ручные операции с базой: `npx wrangler d1 execute ddx-db --remote --command "SELECT login, pro_until FROM users"`.

Эндпоинты: `/auth/register`, `/auth/login`, `/auth/logout`, `/auth/me`, `/auth/password`, `/auth/delete`, `/auth/name`, `/data/get`, `/data/put`, `/pro/activate`. ИИ-запросы теперь требуют заголовок `Authorization: Bearer <токен>`.
